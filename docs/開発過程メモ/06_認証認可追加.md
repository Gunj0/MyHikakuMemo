# 認証認可追加

## Gemini 2.5 Flash 設計書

```text
Next.js のフロントエンド と C# のバックエンドで認証基盤を構築します。以下の要件で計画してください。
1. なるべく独自実装を使わず既存のライブラリを使用する。
2. 認証方法はメールアドレス/パスワードと、Googleログインとする。
```

1. 使用技術とライブラリの選定

| コンポーネント | 技術/ライブラリ       | 採用理由                                                                                     |
| -------------- | --------------------- | -------------------------------------------------------------------------------------------- |
| Next.js        | Auth.js(NextAuth.js)  | 既存の Next.js アプリケーションに簡単に統合できる強力な認証ライブラリ                        |
|                |                       | OAuth（Google）やクレデンシャル認証（メール/パスワード）など複数の認証方式をサポートしている |
|                |                       | Auth.js v5 は Cloudflare の Edge ランタイムに対応している                                    |
| C#/.Net        | ASP.NET Core Identity | C#/.NET の標準的な認証・ユーザー管理システム                                                 |
|                |                       | パスワードのハッシュ化、ユーザー情報の永続化、セキュリティ機能が組み込まれている             |
|                |                       | クレデンシャル認証の管理に利用                                                               |
| 認証プロトコル | JWT (JSON Web Tokens) | ステートレスでスケーラブルな認証を実現するために採用                                         |
|                |                       | API リクエストの認証と認可に使用                                                             |
| 外部認証       | Google OAuth 2.0      | Google ログインを実現するための標準的な認証プロトコル                                        |

2. 認証フローの設計

- A. メールアドレス/パスワード認証 (クレデンシャル認証)
  - 1. フロントエンド (Auth.js)
    - ユーザーがログインフォームにメールアドレスとパスワードを入力
    - Auth.js のクレデンシャルプロバイダーを使用してこれらの情報をバックエンドのログイン API に送信
  - 2. バックエンド (ASP.NET Core Identity)
    - リクエストを受け取り、ASP.NET Core Identity を使用してユーザーを検証（パスワードのハッシュ比較）
    - 認証が成功した場合、ユーザー情報を含む JWT (JSON Web Token) を生成し、フロントエンドに返す
  - 3. API アクセス
    - フロントエンドは受け取った JWT を保持し、保護された API エンドポイントへのリクエスト時に Authorization ヘッダーに添付
    - バックエンドは、リクエストごとに JWT の署名と有効期限を検証し、認可を行う
- B. Google ログイン (OAuth 2.0)
  - 1. フロントエンド (Auth.js)
    - ユーザーが「Google でログイン」ボタンをクリック
    - Auth.js の Google プロバイダーが、Google 認証サーバーへユーザーをリダイレクト
  - 2. Google 認証サーバー
    - ユーザーが Google 側でログインと認可を行う
    - 成功後、Auth.js のコールバック URL に認可コード/トークンが返される
  - 3. フロントエンド / Auth.js
    - Auth.js は受け取った情報(ユーザー情報、トークン等)を使用してユーザーを認証済みの状態にし、バックエンドのユーザー登録/連携 API にアクセス
  - 4. バックエンド (ASP.NET Core Identity)
    - Auth.js から送信された Google のユーザー情報(メールアドレス等)を受け取り、ASP.NET Core Identity を使用して以下の処理を行う
      - 既存ユーザー：外部アカウント連携として情報を更新
      - 新規ユーザー：新しいアカウントを作成
    - 処理後、認証済みのユーザー情報に基づいて JWT を生成し、フロントエンドに返す

3. Program.cs 修正

```cs
// Identity設定
builder.Services.AddIdentity<ApplicationUser, IdentityRole>(options =>
{
    options.Password.RequireUppercase = true; // 大文字必須
    options.Password.RequireLowercase = true; // 小文字必須
    options.Password.RequireDigit = true; // 数字必須
    options.Password.RequireNonAlphanumeric = false; // 記号は不要
    options.Password.RequiredLength = 8; // 最小文字数
    options.User.RequireUniqueEmail = true; // メールアドレスの一意性
})
.AddEntityFrameworkStores<ApplicationDbContext>() // EF Coreストアを使用
.AddDefaultTokenProviders(); // トークンプロバイダーを追加

// JWT認証設定
builder.Services.AddAuthentication(options =>
{
    // JWT Bearerトークンをデフォルトの認証スキームとして設定
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    // JWT Bearerトークンをデフォルトのチャレンジスキームとして設定
    options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(options =>
{
    options.TokenValidationParameters = new TokenValidationParameters
    {
        ValidateIssuer = true, // 発行者の検証を有効化
        ValidateAudience = true, // オーディエンスの検証を有効化
        ValidateLifetime = true, // トークンの有効期限の検証を有効化
        ValidateIssuerSigningKey = true, // 署名鍵の検証を有効化
        ValidIssuer = builder.Configuration["Jwt:Issuer"] // 発行者の設定
            ?? throw new InvalidOperationException("JWT発行者が見つかりません"),
        ValidAudience = builder.Configuration["Jwt:Audience"] // オーディエンスの設定
            ?? throw new InvalidOperationException("JWTオーディエンスが見つかりません"),
        IssuerSigningKey = new SymmetricSecurityKey( // 署名鍵の設定
            System.Text.Encoding.UTF8.GetBytes(
                builder.Configuration["Jwt:SecretKey"]
                    ?? throw new InvalidOperationException("JWTシークレットキーが見つかりません")
            ))
    };
});

// コントローラ追加
builder.Services.AddControllers();

var app = builder.Build();

// DBマイグレーション
using (var scope = app.Services.CreateScope())
{
    var context = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
    context.Database.Migrate();
}

// 認証ミドルウェアを必ず認可ミドルウェアの前に配置
app.UseAuthentication();
app.UseAuthorization();

// コントローラをマッピング
app.MapControllers();
```

"Jwt": {
  // 256bit(32byte)以上のランダムな秘密鍵
  "SecretKey": "This-Is-A-Very-Strong-Secret-Key-Used-For-JWT-Signing-1234567890",
  "Issuer": "http://localhost:5000", // APIのURL
  "Audience": "http://localhost:3000" // Next.jsのURL
}
